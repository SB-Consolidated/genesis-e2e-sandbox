# Screen-002-Add-Task — Questions

## Founder Decisions (Resolved)

1. **Fold the add field into the task list**
   - Decision: The add control is part of the single-page task list and sits at the top.
   - Outcome: The form is embedded directly into the main screen instead of acting as its own route.

2. **No separate add route**
   - Decision: There is no `#/add` or dedicated add screen.
   - Outcome: The user remains on the same page and continues working from the list.

3. **Simple, mobile-friendly flow**
   - Decision: The experience should remain lightweight and easy to use on mobile devices.
   - Outcome: Minimal controls, low friction, and a single visible creation action.

4. **Enter submits the form**
   - Decision: Pressing Enter submits the task directly from the input.
   - Outcome: The interaction is quick and consistent without requiring a mouse.

## Remaining Status
- No unresolved product questions remain for this screen.
- The founder’s decisions settle the placement, routing, and input behavior for the inline add flow.
- The task list and add field are treated as one combined single-page experience.
